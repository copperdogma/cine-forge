## High-Leverage Findings

### 1. Frontend chat/data layer is concentrated in oversized, high-churn files

- Classification: Story
- Why it matters: The repo is currently shipping UI-heavy work, but the highest-churn UI behavior lives in a few files that each mix multiple responsibilities. That makes every new UI feature riskier, slower to review, and more likely to create incidental regressions in unrelated flows.
- Evidence: `ui/src/components/ChatPanel.tsx` is 1,257 lines with 18 edits in the last 30 days and mixes rendering, streaming orchestration, mention autocomplete, resize behavior, tool/action handling, and role stickiness. `ui/src/lib/hooks.ts` is 909 lines with 19 edits and mixes React Query hooks, entity resolution, scene transformation, chat bootstrapping, navigation, and export aggregation. `ui/src/lib/api.ts` is 771 lines with 15 edits and centralizes every request path from project creation through design-study export. No equivalent decomposition story exists in `docs/stories.md`.
- Recommendation: Draft a focused UI decomposition story that splits domain hooks from cross-cutting utilities, breaks `ChatPanel` into orchestration + presentational pieces, and slices `api.ts` by resource domain without changing routes or behavior.

### 2. Backend chat orchestration remains a 2,191-line monolith

- Classification: Story
- Why it matters: The chat system is the main expression of the Ideal's "creative partnership" requirement. Right now a single file owns prompt construction, role routing, tool execution, pipeline-graph formatting, Anthropic transport, transcript compaction, prompt caching, and streaming loops. That is too much blast radius for one of the most user-visible subsystems.
- Evidence: `src/cine_forge/ai/chat.py` is 2,191 lines. Function clusters span project-context/prompt building (`compute_project_state`, `_build_project_context`, `build_role_system_prompt`, `build_character_system_prompt`), tool execution (`execute_tool`, `_execute_propose_artifact_edit`, `_execute_propose_run`), transport (`_stream_anthropic_sse`, `_call_anthropic_sync`), and transcript lifecycle (`_estimate_tokens`, `_compact_transcript`, `_add_cache_breakpoints`, `_stream_single_role`). Existing stories add features to this file (for example Story 084) but no story currently decomposes it.
- Recommendation: Create a backend chat-architecture story that extracts prompt builders, tool execution, transport/client code, and transcript compaction into focused modules with unchanged external behavior.

### 3. Foundational AI modules still combine orchestration, prompting, QA, and test-mode helpers

- Classification: Story
- Why it matters: `script_normalize_v1` and `character_bible_v1` sit on the hot path for early pipeline quality. Both are still growing as single-file coordinators, which makes targeted fixes harder and increases the chance that eval or fixture changes spill across unrelated behavior.
- Evidence: `src/cine_forge/modules/ingest/script_normalize_v1/main.py` is 1,080 lines with 15 edits in the last 30 days and includes tier classification, smart-chunk normalization, QA loops, export annotations, patch parsing, and mock helpers in one file. `src/cine_forge/modules/world_building/character_bible_v1/main.py` is 928 lines with 16 edits and combines candidate adjudication, full/minor extraction flows, QA, prompt builders, name sanitation, and artifact assembly. `src/cine_forge/ai/llm.py` is an adjacent 855-line dependency, which raises the payoff for making module boundaries explicit instead of letting each caller grow ad hoc logic.
- Recommendation: Add a decomposition story for the extraction/normalization layer, starting with `script_normalize_v1` first. Extract prompt-building, QA/retry coordination, and output-assembly helpers behind stable function boundaries before adding more module behavior.
