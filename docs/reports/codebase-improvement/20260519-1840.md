### 1. Render adapter is now the active scene-generation monolith

- Classification: Story
- Why it matters: The active `spec:6` / `spec:7` product lane keeps adding render, AI-previz, default reference, clip planning, provider, and artifact-truth behavior. The render adapter now concentrates too much of that lane in one file, so future scene-generation fixes will keep landing as surgical edits in a 2,630-line owner unless the repo creates an explicit extraction story.
- Evidence: `src/cine_forge/modules/generation/render_adapter_v1/main.py` is 2,630 lines, the largest Python source file and still among the recent source hotspots. The file owns module orchestration, default design-study backfill calls, render-clip selection, required clip-plan enforcement, render execution, source-map assembly, resolved input/reference selection, provider request shaping, render/previz prompt block assembly, dialogue contract repair, artifact dictionaries, cost merging, and track-manifest updates. Story 191 saw the file at 1,823 lines, Story 193 at 1,985, Story 202 at 2,466, and each story explicitly warned to keep changes narrow. ADR-002 and ADR-003 both apply: downstream generation must expose honest preflight/default truth, and prompts are compiled artifacts rather than editable source of truth.
- Recommendation: Draft a decomposition story that extracts four focused owners without changing behavior: render-unit orchestration/failure handling, resolved-input/reference selection, prompt context/dialogue contract assembly, and artifact/cost/track-output builders.
